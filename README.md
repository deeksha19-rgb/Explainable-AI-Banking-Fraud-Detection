# Explainable AI Fraud Detection — PaySim Upgrade

This upgrade adds a separate PaySim workflow while preserving the original synthetic-data project, source files, and `outputs/`. The PaySim workflow writes only to `outputs_paysim/`.

> **Data integrity note:** PaySim is a synthetic mobile-money transaction dataset generated by a simulator informed by real transaction data. It is not a collection of genuine bank transactions. Use this description in reports, demos, and your resume.

## 1. Add the original dataset

Download the dataset from https://www.kaggle.com/datasets/ealaxi/paysim1. Extract the archive and place the original CSV here:

```text
data/raw/PS_20174392719_1491204439457_log.csv
```

Do not edit or resave the source CSV. The training script reads only `step`, `type`, `amount`, and `isFraud`, leaving the original file unchanged. If your CSV has a different filename, the script also accepts exactly one `.csv` file in `data/raw/`.

## 2. Install and inspect

Run from this project directory in the VS Code terminal (Windows):

```powershell
py -m pip install -r requirements.txt
py -m src.inspect_paysim
```

## 3. Train and evaluate

```powershell
py -m src.train_paysim
```

The training script uses a chronological 70%/10%/20% train/validation/test split based on `step`. For a laptop-friendly first run, it keeps every fraud record in the training period and samples legitimate records at up to 30:1; sample weights compensate for this sampling when fitting. Validation/test metrics are calculated on their original class distributions. Training and validation can still take time because the source dataset contains millions of rows.

Outputs are written to `outputs_paysim/`: model, metrics, baseline, global permutation importance, and scored held-out transactions. The previous `outputs/` files are not overwritten. **Do not report any PaySim metrics until this script finishes successfully.**

## 4. Launch the PaySim dashboard

```powershell
py -m streamlit run app_paysim.py
```

Use `app_paysim.py` for PaySim. The original `app.py` still belongs to the earlier synthetic-data version and is preserved for reference.

## Feature and leakage decisions

- Target label: `isFraud`.
- Primary inputs: `step`, `type`, `amount`; derives `hour_of_day = step % 24`.
- Excluded from the primary model: `isFlaggedFraud` (an existing rule-based flag), `oldbalanceOrg`, `newbalanceOrig`, `oldbalanceDest`, `newbalanceDest` (balance fields can expose simulated transaction outcomes), and `nameOrig`/`nameDest` (account identifiers).
- `step` is an hourly simulation index, not a real-world timestamp.
- Local dashboard explanations are one-feature-at-a-time comparisons against a typical legitimate baseline. They are approximate diagnostics, not exact SHAP values or causal explanations. Global permutation importance is computed on a bounded random sample of the held-out test set.

## Project files added

- `src/inspect_paysim.py` — checks file location and displays the schema using a small sample.
- `src/paysim_features.py` — PaySim-specific features and model candidates.
- `src/train_paysim.py` — chronological training, threshold selection, evaluation, and output generation.
- `app_paysim.py` — PaySim dashboard.
- `README_synthetic_original.md` — original project README, retained unchanged.

## Limitations

PaySim is simulated and does not establish how a model will perform on a real bank's data. The first version uses a compact set of fields and does not yet build customer-history or graph features. Thresholds are selected on validation data and can change the trade-off between missed fraud and review volume.
